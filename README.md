# Customer Shopping Behavior Analysis

An end-to-end data analytics project exploring customer purchasing patterns, product performance, discount usage, shipping preferences, and subscription behavior using **Python, MySQL, and Power BI**.

## Project Overview

This project analyzes a dataset containing **3,900 purchase records and 18 original columns**. The goal is to turn raw shopping data into useful business insights that can support customer segmentation, marketing, product positioning, and subscription strategies.

## Tools & Technologies

- **Python:** Pandas, NumPy
- **SQL:** MySQL
- **Visualization:** Power BI
- **Notebook:** Jupyter Notebook

## Project Workflow

1. **Data loading and exploration**
   - Loaded the CSV dataset with Pandas.
   - Reviewed the structure with `df.info()` and summary statistics with `df.describe()`.
   - Checked missing values.

2. **Data cleaning and preparation**
   - Found 37 missing values in `Review Rating`.
   - Imputed missing ratings using the median rating within each product category.
   - Standardized column names to `snake_case`.
   - Created an `age_group` feature using age quantiles.
   - Converted purchase-frequency labels into an approximate number of days.
   - Checked the relationship between `discount_applied` and `promo_code_used`, then removed the redundant `promo_code_used` column.

3. **SQL analysis**
   - Loaded the prepared data into a MySQL table named `customer_shopping`.
   - Wrote SQL queries to answer ten business questions.

4. **Power BI dashboard**
   - Built an interactive dashboard with KPI cards, category charts, age-group comparisons, subscription-status breakdowns, and slicers for exploring the data.

## Business Questions Answered

The SQL analysis explores:

1. What is the total revenue generated by male and female customers?
2. Which customers used a discount but spent at least the average purchase amount?
3. Which five products have the highest average review ratings?
4. How do average purchase amounts compare between Standard and Express shipping?
5. How do average spend and total revenue compare between subscribers and non-subscribers?
6. Which five products have the highest percentage of purchases with discounts applied?
7. How many customers fall into New, Returning, and Loyal segments based on previous purchases?
8. What are the top three most-purchased products within each category?
9. How many repeat buyers (more than five previous purchases) are subscribers versus non-subscribers?
10. How much revenue does each age group contribute?

## Selected Findings

The following figures are from the analysis report and dashboard included with this project:

- **3,900** purchase records analyzed.
- **$59.76** average purchase amount shown on the Power BI dashboard.
- **3.75** average review rating shown on the dashboard.
- Average purchase amount was **$60.48 for Express shipping** and **$58.46 for Standard shipping**.
- The report's subscription comparison showed average spend of **$59.49 for subscribers** and **$59.87 for non-subscribers**. In this dataset, subscribers did not have a higher average purchase amount.
- The highest discount rate among the five products listed in the SQL results was **Hats at 50.00%**.
- The report's customer segmentation counted **3,116 Loyal**, **701 Returning**, and **83 New** records under the project's defined rules.
- The age group with the highest reported revenue was **Young Adult ($62,143)**.

These are descriptive findings from this dataset, not proof that one factor caused another or that the same pattern will hold for every retailer.

## How to Run the Project

### 1. Requirements

Install Python and Jupyter Notebook. The notebook uses Pandas and NumPy. For the MySQL integration, the notebook also uses SQLAlchemy and PyMySQL.

```bash
pip install pandas numpy sqlalchemy pymysql jupyter
```

### 2. Prepare the dataset

Place `customer_shopping_behavior.csv` in the same directory as the notebook, then open the notebook:

```bash
jupyter notebook Customer_Shopping_Behavior_Analysis.ipynb
```

Run the cells in order to explore and clean the data.

### 3. Load the cleaned data into MySQL

- Install and start MySQL Server.
- Create the database and table connection expected by the notebook.
- Update the connection details in the notebook for your own local MySQL setup.
- **Do not commit database passwords or other credentials to GitHub.** Use environment variables or a local configuration file excluded from version control.
- Run the notebook's database-loading cells to write the cleaned DataFrame to the `customer_shopping` table.

### 4. Run the SQL analysis

Open `Customer_Shopping_Behavior_Analysis_MySQL_query.sql` in MySQL Workbench or another MySQL client, select the `customer_behavior` database, and execute the queries. Make sure the table name and column names match your imported dataset.

### 5. Open the Power BI dashboard

Open `Customer_Shopping_Behavior_Dashboard.pbix` in Power BI Desktop. If the report asks for a data source, reconnect it to your local data source and refresh the report.

## Key Business Recommendations

Based on the analysis report:

- **Grow subscriptions:** Test exclusive subscriber benefits and measure whether they improve retention and spending.
- **Encourage loyalty:** Consider rewards for repeat customers and track repeat-purchase behavior.
- **Review discount strategy:** Compare discount-driven sales with profitability before increasing promotions.
- **Improve product positioning:** Feature well-rated and frequently purchased products in relevant campaigns.
- **Use targeted marketing:** Tailor campaigns to customer segments and age groups, validating performance with further analysis.

## Limitations & Notes

- The analysis is based on the provided dataset and its available fields.
- The project report documents 37 missing review ratings, which were imputed using category-level medians.
- The customer-segment labels follow the rules implemented in the notebook/SQL; they are project-specific definitions.
- The dashboard file may require its original data source to be reconnected on another computer.
- The SQL script is written for **MySQL**. The accompanying report mentions PostgreSQL in one section, but the provided SQL syntax and notebook connection are MySQL-oriented.
